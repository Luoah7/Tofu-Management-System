# v0.3.1 批量导入识别率优化规划

## 目标

v0.3.1 聚焦批量导入的识别率、稳定性和模型调用成本。目标是让日常微信订货文本优先由本地规则识别，只有本地无法判断的片段再交给大模型兜底。

核心结果是三点：常见口语订单能直接生成预览，商品和规格匹配更稳，模型账单能看出调用减少。

## 当前问题

批量导入现在能处理标准格式和一部分口语格式，但真实订货文本更随意。常见问题包括中文数字没有完全覆盖，商品别名不足，规格关键词不足，商户和商品不写冒号时容易丢失，多个商品黏在一句话里时拆分不够稳。

模型调用也需要收紧。之前只要配置模型，订单解析和规格匹配都容易触发模型。v0.3.1 要保持规则优先，模型只处理未识别片段，不能整段反复请求。

## 范围

本版本只处理批量导入，不做 OCR 截图识别，不做商户自助下单，不改主业务状态流。

会改的范围包括订单文本预处理、本地订单解析、商品别名、规格关键词、模型兜底策略、导入预览的识别结果提示和回归测试。

## 解析规则

文本预处理需要支持全角半角统一、中文数字转阿拉伯数字、常见时间词清理、多个分隔符统一。比如 `明早`、`明天早上`、`后天` 只用于判断日期或清理语义，不应该污染商品名。

订单行需要支持冒号格式和空格格式。比如 `东桥：豆腐2筐，豆干3斤`、`东桥 明早豆腐一筐豆干三斤` 都应该识别为同一个商户的订单。

商品项需要支持商品名和数量黏连。比如 `豆腐2筐`、`豆干三斤`、`未调味豆干3斤`、`精品豆腐一筐` 都应该拆出商品、规格、数量和单位。

数量单位继续保留 `斤`、`公斤`、`筐`。其中 `筐` 默认换算为 12 斤。中文数字需要覆盖 `一二三四五六七八九十两半`，小数先不作为主目标。

## 商品和规格字典

新增本地别名字典。商品别名用于把客户口语映射到系统商品，比如 `干子`、`香干` 映射豆干，`一盘`、`一筐` 在没有商品名时默认映射豆腐。

新增规格关键词。比如 `精品`、`好豆腐` 匹配精品豆腐，`未调味`、`不调味`、`原味`、`白豆干` 匹配未调味豆干，`调味`、`五香` 匹配调味豆干。

规格匹配规则优先使用关键词。只有商品能确定但规格无法确定时，才允许进入人工确认或模型兜底。

## 模型兜底

模型不再处理整段订单。流程改为本地先解析，未识别片段单独进入模型。

模型请求只带必要上下文，包括未识别原文、可选商户列表、商品列表、规格列表和固定 JSON 返回格式。模型返回结果必须进入预览，不允许直接新增任务。

模型结果需要标记来源。预览里区分规则识别和模型识别，模型识别的低置信项需要用户确认。

## 导入预览

预览需要展示识别来源和风险提示。规则命中的正常展示，模型兜底的显示需要确认，无法识别的放到未识别区域。

每个商户详情仍然可以编辑商品、规格、单位和数量。用户确认后才创建任务。

## 日志和统计

批量导入接口返回识别统计，不存敏感原文。统计包括总行数、规则命中数、模型兜底数、未识别数、跳过商户数。

服务端日志只记录数量和失败原因，不记录完整订单文本。

## 验收标准

以下文本应能本地规则识别，不调用模型。

```text
东桥 明天早上一盘
刘记 明天送豆腐，黑豆腐少送，豆干3斤
东桥超市：精品豆腐一筐，未调味豆干三斤
老王 豆腐2筐 豆干5斤
散户：黑豆腐1筐，脆皮豆腐2斤
```

无法确定数量的文本不能乱编数量，必须进入人工确认。

```text
黑豆腐少送
豆干少来点
豆腐照旧
```

批量导入普通订单时，模型调用次数应为 0。只有包含本地规则无法识别片段时，才允许模型调用。

## 测试计划

新增中文数字解析测试、商品别名测试、规格关键词测试、混合口语订单测试、模型调用守卫测试。

保留现有单位换算、规格匹配和批量导入回归测试。

## 版本记录文案

v0.3.1 优化批量导入识别率。新增口语订单解析、商品别名、规格关键词和模型调用守卫。普通订单优先走本地规则，未识别片段才进入模型兜底，降低误识别和模型成本。
